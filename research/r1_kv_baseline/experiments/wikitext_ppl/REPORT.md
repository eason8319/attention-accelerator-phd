## 1. 实验目的

在协议主 Pareto 模型上补 **y 轴**，使 `kv_pareto` 的 bytes/token 能画成精度—流量曲线。回答：

1. C0–C5 在 Llama-3.1-8B 上能否加载、短序列前向与贪心生成？  
2. WikiText-2 test、窗口 4K/8K/16K/32K 上，各格式相对同窗口 C0 codec 的 PPL 差多少？格式排序是否随窗口改变？

KIVI 评估 Table 3 / LongBench **不能**替代：模型不同，且KIVI 评估的 C0 是原生 HF。

---

## 2. 方法与设置

### 2.1 被测格式

| ID | 入口 | 路径 |
|----|------|------|
| C0 | `c0` / `fp16_codec` | FP16 **codec** cache-path |
| C1 | `int8` | 均匀 INT8 |
| C2 | `int4` | 均匀 INT4 |
| C3 | `int4_bdr` | INT4 + BDR |
| C4 | `kivi2` | KIVI 2-bit |
| C5 | `kivi4` | KIVI 4-bit |

布局 contiguous（paged 数值分页布局已对齐，主 Pareto 精度不双跑）。KIVI：`group_size=32`，`residual_length=128`。禁止投影 fake-quant。C0 禁止原生 HF `fp16`。

### 2.2 指标与负载

- Golden：同一模型、同一脚本下的 C0 codec PPL。  
- $\Delta$：该格式 PPL − C0 PPL。  
- 冒烟：短 prompt（40 token）；前向 logits 有限；贪心 `max_new_tokens=8`。不作精度主张。  
- PPL：`Salesforce/wikitext` / `wikitext-2-raw-v1` **test**；滑动窗口 `max_length=4096/8192/16384/32768`，`stride=512`；每窗只对新增 token 做 teacher-forcing CE；$\mathrm{PPL}=\exp(\mathrm{NLL}/N)$。
- 各窗口计分 token 数均为 $288936$，序列长 $288937$；4K/8K/16K/32K 的窗口数分别为 558/550/534/502。8K 原始配置的 `query_chunk=1024`，16K 与 32K 为 256；这是计算分块参数，不能混淆为上下文窗口。

墙钟平台：`node7`，NVIDIA GeForce RTX 4090（24 GB），`torch=2.5.1+cu121`。作业 19227（冒烟）→ 19228（PPL，`afterok`）。计算节点 `HF_HUB_OFFLINE=1`。

本地保存实验源码、`results/smoke/smoke.json` 和四个窗口各自的 `ppl_summary.json`，后者包含全部 24 条计分记录。入口使用 r1_kv_baseline 主库，当前依赖和历史源码归档见 `experiment.json`；运行还需要依赖环境和模型权重。

## 3. 实验结果

### 3.1 短序列冒烟（19227，1.9 min，6/6 PASS）

| 格式 | patched | logits 有限 | 新 token | 峰值显存 |
|------|:-------:|:----------:|--------:|--------:|
| C0–C5 | 是 | 是 | 8 | $\approx 15.3$ GiB |

六种格式贪心续写相同（`In this article, Turing proposed a test`）。prompt+生成共 48 token，短于残差窗 128，KIVI 量化不生效。只说明路径通，**不能**当精度证据。

### 3.2 WikiText-2 PPL（19228，58 min）

| ID | 格式 | PPL | $\Delta$ vs C0 | 相对 C0 |
|----|------|----:|---------------:|--------:|
| C0 | `c0` | $6.264$ | — | $1$ |
| C1 | `int8` | $6.265$ | $+0.001$ | $+0.01\%$ |
| C2 | `int4` | $6.435$ | $+0.171$ | $+2.7\%$ |
| C3 | `int4_bdr` | $6.363$ | $+0.098$ | $+1.6\%$ |
| C4 | `kivi2` | $7.568$ | $+1.304$ | $+20.8\%$ |
| C5 | `kivi4` | $6.291$ | $+0.026$ | $+0.42\%$ |

C5 与 C0 的差约 0.026；C1 的原始差为 0.000548，三位小数显示为 6.265 与 6.264，不能称为三位小数不可分。C3 低于均匀 INT4，C4 的 PPL 增幅最大。

| 格式 | 4K PPL | 8K PPL | 16K PPL | 8K $\Delta$ vs C0 | 16K $\Delta$ vs C0 |
|---|---:|---:|---:|---:|---:|
| C0 | 6.264 | 6.224 | 6.256 | 0.000 | 0.000 |
| C1 INT8 | 6.265 | 6.225 | 6.257 | +0.001 | +0.001 |
| C2 INT4 | 6.435 | 6.401 | 6.437 | +0.177 | +0.181 |

各窗口均有六个 `ok=true` 的结果；差值由未舍入的原始 PPL 计算。32K 汇总于 2026-09-08 20:46 UTC（北京时间 9 月 9 日 04:46）写出；此前三份单格式结果已与最终汇总核对。

|---|---:|---:|---:|
| C0 | 6.316474 | 0 | 4096 |
| C1 INT8 | 6.317325 | +0.000852 | 2080 |
| C2 INT4 | 6.476872 | +0.160398 | 1152 |
| C3 INT4+BDR | 6.433739 | +0.117265 | 1152 |

### 3.4 与 4K 流量合成的 Pareto 点

x 轴取 [`kv_pareto`](../kv_pareto/REPORT.md) 全模单步 bytes/token、$N{=}4096$、contiguous（与 PPL 窗口对齐）。C2 与 C3 流量相同。

| 格式 | bytes/token (MiB) | 相对 C0 流量 | PPL |
|------|------------------:|-------------:|----:|
| C0 | $512$ | $1$ | $6.264$ |
| C1 | $260$ | $0.508$ | $6.265$ |
| C2 | $144$ | $0.281$ | $6.435$ |
| C3 | $144$ | $0.281$ | $6.363$ |
| C4 | $102.5$ | $0.200$ | $7.568$ |
| C5 | $165.5$ | $0.323$ | $6.291$ |

在 4K 上：C5 用约 C0 $32\%$ 的 KV 流量，PPL 只高 $0.026$。C4 流量最低（约 $20\%$），PPL 高 $1.30$。C3 与 C2 同流量，PPL 更好。

## 4. 分析与讨论

在四组已完成窗口中，C5 相对 C0 的 PPL 增量为 0.026–0.029，C3 始终低于同名义流量的 C2；C4 的增量从 4K 的 1.304 增至 32K 的 1.440。该观察限于当前模型与语料，不代表统计显著性或其他任务上的普遍排序。C0 从 4K 到 8K 再到 16K 的 PPL 并非单调下降，不能把扩大窗口直接解释为必然改善。

| 格式 | 优势 | 劣势 / 适用边界 |
|------|------|----------------|
| **C0** | 未量化参考；与流量表同一 codec | 流量最大 |
| **C1** | 流量约一半，PPL 几乎不变 | 压缩幅度不如 4-bit |
| **C2** | 流量 $28\%$ | PPL $+0.17$，弱于 C3/C5 |
| **C3** | 同 C2 流量，PPL 优于均匀 INT4 | BDR 旋转在片上，实现更重 |
| **C4** | 本谱最低流量 | PPL $+1.30$（相对 $+21\%$） |
| **C5** | PPL 接近 C0，流量约 $32\%$ | 流量高于 C2/C4（残差 FP16 窗） |

**综合（4K WikiText-2）**：

1. **较低精度退化的 4-bit 候选**：C5；本实验未验证部署性能。
2. **同流量下要更好的 4-bit**：C3 优于 C2。  
3. **极限压流量并接受 PPL 上升**：C4。  
4. **未量化对照**：C0；INT8 与 C0 的数值差很小。

与KIVI 评估任务分方向一致：KIVI-4 ≈ C0，KIVI-2 可见掉点、未崩。与 `codec_compare` 合成 C4 误差过大不可互换。

## 5. 局限与有效性

- 四个窗口均已完成；结果为单次评测，不提供置信区间。完整测试集 PPL 不等同于真实长对话生成质量。
- 未跑 paged 精度（分页布局已对齐数值，主表不双跑）。  
- 未与论文公开 WikiText PPL 并表。  
- Instruct 模型在 WikiText 上不是语言建模最优设定；只作本仓库相对 $\Delta$。  
- `attn_implementation=eager`；墙钟不是吞吐上限。  
- 单次评测、无多种子。  
- 冒烟序列短于残差窗，不能代表量化打开后的生成质量。

## 6. 结论与后续工作

- 8B 上 C0–C5 cache-path 冒烟 6/6；WikiText-2 test 4K/8K/16K/32K 的六种格式均完成。
- **C5 ≈ C0**（$+0.026$）；**C4 $+1.30$**；C3 优于均匀 INT4。  
- 与 `kv_pareto` $N{=}4\mathrm{K}$ 流量可画第一条 bytes/token–PPL 曲线。
