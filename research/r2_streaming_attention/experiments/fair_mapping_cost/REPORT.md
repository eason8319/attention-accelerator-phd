# 公平映射与周期、能耗基线

实验日期：2026-09-17；整理日期：2026-09-17。完成范围：双模型几何、四主格式和双布局下的优化 FP16、共享流式解码、GQA/跨头/KV-split 对照，以及动作计量、容量检查、逐步压力轨迹和参数敏感性。原始证据位于 [`results/mapping_cost_accounted/`](results/mapping_cost_accounted/summary.json)，源码、配置、依赖和哈希见 [experiment.json](experiment.json)。审核状态只在[里程碑](../../../../docs/progress/milestones.md#r2-review)维护。

本实验是单层 attention-only 架构模型。模型名称表示几何来源，不表示加载权重或运行整模质量评测；独立组合仍按协议留给后续步骤。

## 1. 实验目的

1. 在相同 MAC、SRAM、带宽及操作数端口预算下，建立优化 C0 FP16 和同格式共享流式解码基线，判断压缩带来的流量、动态能量与周期变化。
2. 区分逻辑分段和物理并行，检验 GQA 共享、跨 KV head 和 KV-split 的计算量、供给、状态归并与缓冲代价。
3. 对 C3 混合功能路径计入写侧旋转、读侧 K 逆旋转、FP16 V 尾部旋转、输出逆旋转和短块补零，判断其成本适用性。
4. 核验追加、刷窗、元数据与读改写事件，保存完整压力轨迹，明确参数不确定性和不可行配置。

## 2. 方法与设置

### 2.1 协议、资源和数据流

评测协议为 [`r2-evaluation-v2`](../configs/evaluation_protocol.json)，实现参数为 [`r2-mapping-cost-v2`](../configs/mapping_cost.json)。缺省配置为 1,024 MAC、32×32 PE、16 MiB SRAM、1 TB/s HBM、解量化 128 元素/周期、单操作数端口。Llama 几何为 32 Q / 8 KV / head_dim=128；Qwen 为 28 Q / 4 KV / head_dim=128。主点为 T=4096、batch=1、contiguous/paged，格式为 C0/C2/C3/C5。

阵列采用明确的 output-stationary 映射：query 对应 PE 行，QK 的 token 或 PV 的 channel 对应列；尾行、尾列空闲。每个矩阵块使用声明的 2 周期启动成本。阵列利用率由实际动作数、物理 MAC 预算和调度完成时间计算，不把逻辑 head/split 数量直接当作利用率。C3 的逐头旋转按最多 16 行、32×32 旋转块计时，输出逆变换单独计算。

活动 split 通路数为 `min(kv_split, operand_ports)`，通路均分 PE 行及计算侧供给吞吐。超过端口数的逻辑分段在通路内复用该份额；单端口不会因为 split=4 而只使用四分之一阵列。跨头并行受同一端口约束，跨头与 split 同时扩展的组合不在本模型支持范围。GQA 展开保留全部查询的 QK/PV 运算，同时重复读取和解码 KV。

DMA 为单引擎、队列深度 4、32 B 对齐、每事务启动 16 周期。依赖图显式记录 K 读取、计算、V 读取及缓冲释放；双缓冲仅允许在空闲槽内预取。不同计算通路共用 DMA，组件服务周期之和表示串行工作量，并行墙钟由调度器另外给出。SRAM 为 32 bank、2 rw 端口、256 bit、2 周期延迟；一个 rw 端口给 DMA，其余供计算，顺序访问按无 bank 冲突处理。DMA 吞吐还受其 SRAM 写入口限制，不能仅由 HBM 带宽决定。

连续地址按当前计算块供给，不要求整侧历史进入 SRAM。分页按相交物理页计量；分离的 payload 和 metadata 分别发事务，C5 Key 的尺度/min 在同一供给范围内按 group 复用。连续布局的事务是地址合并后的架构模型，不等同于 Python append 块逐一 `scan_read` 的事务次数。工作缓冲包含 Q、当前及归并输出、softmax 状态、score/weights、单头操作数组、压缩载荷、scale/min、尾页/残差、量化暂存、地址队列和旋转矩阵；低比特路径不保存完整高精度历史 KV 副本。

### 2.2 动作计量和能量参数

基础单位是一层一步。HBM 主列包含 KV 读取、追加写入、Value 尾页读改写，以及 Q 读取、O 写回；KV 专用列和可比 R1 的逻辑读取另存。SRAM 记录缓存事件和工作缓冲读写，按访问流对齐到 SRAM 字后计算物理字节。写侧量化、打包、FP16 转换、页表/标签、地址控制、广播、输出重缩放、归并和最终归一化分别入账；batch=4 使用时间复用，各动作和周期同步乘四。

C5 保持紧凑残差布局：刷出 Value 后保留部分仍需 SRAM 搬移，未假定免费的环形缓冲；已有未满 Value 量化页需要读改写。C3 混合通路为原域 QK、旋转域 PV/O；分页满页提交时进行写侧旋转，未提交的 FP16 V 尾部在读取时旋转。短块补零不进入有效 softmax 列。

动态能量按动作数乘单位能量计算。HBM2 使用固定 Accelergy CACTI 插件提交中的 3.9 pJ/bit；MAC 使用 ISPASS 2020 教程的 16-bit、45 nm 示例 5 pJ。来源和证据边界见[既有 Accelergy 文献卡片](../../../../docs/recent_works_comparison.md#accelergy)。这些参数均不是本阵列的硅片测量；功能参考的 FP32 精度也不证明硬件算术已经实现。

SRAM 0.05 pJ/bit、解量化 1 pJ/元素、softmax 5 pJ/计量项、广播 0.005 pJ/B，以及量化 6 pJ/元素、打包 1 pJ/B、控制 1 pJ/事件、转换 1 pJ/元素，均为未校准实现假设。量化项覆盖统计、尺度、舍入和夹紧。辅助吞吐声明为：softmax/归一化 32 项/周期、量化与转换 128 元素/周期、打包 32 B/周期、控制 1 事件/周期、广播扇出 128 B/周期；与阵列、SRAM 一起约束服务时间。配置保存来源、45 nm 类别、1.1 V、25 ℃及敏感性范围；它们不构成联合工艺标定。

主表仅报告所列动作的动态能量。漏电缺少实测参数，另以 0/10/50 mW 做持续时间积分，不作为零漏电假设计入主表。1 GHz 仅用于参考时间换算，步骤 2 的 1 ns 综合探针未通过。

### 2.3 网格、检查与复现

开发主网格 16 格，映射对照 30 格，单因素 62 格，优化 16 格，增加端口的资源变体 24 格。主网格、优化、容量、端口变体和压力覆盖四格式；映射对照与单位能量敏感性覆盖 C0/C2/C3，开发单因素覆盖 C0/C2。每个格式/布局在同一 24 候选空间选周期最小、动态能量次之的可行点：tile=128/512、单/双缓冲、K/V 分开/同块预取、split=1/2/4。归并范围固定 128，所以实际计算块不超过 128 token；tile=2048 另有 64 个缓冲预约检查，不进入选优。

压力测试为 Llama 分页几何的 D(16384,1024)：保存长度 16384–17407 的全部 1024 步，长度定义为该步追加后进行 attention 的缓存长度。四种格式共 4096 个步骤均保留动作、占用、组件成本和调度结果。这是几何压力，不是自由生成质量。

检查包含占用与实际物理缓存对拍、逐 token 追加/读取事件对拍、手算调度、查询计算量、MAC 预算、SRAM 带宽约束、能量闭合、batch 计数、搜索范围和轨迹完整性。事件对拍覆盖两种几何、四格式、双布局、元数据分离/共址及 13 个边界长度，共 416 组。开发组合点仅使用协议既定 `shared_bandwidth_balance`，没有读取步骤 8/12 的独立组合。

环境为 WSL2 CPU、Python 3.11.15、PyTorch 2.13.0+cpu、NumPy 2.4.6，单线程；可移植依赖见 [`runtime/dependencies.json`](runtime/dependencies.json)。不需要 GPU 或模型权重。从项目根目录运行：

```bash
conda activate r1-kv-baseline
python research/r2_streaming_attention/experiments/fair_mapping_cost/run_mapping_cost.py \
  --output results/mapping_cost_reproduction --threads 1 --no-register
```

输出路径相对实验目录解析，非空目录会被拒绝。`--no-register` 保留当前权威清单；省略时仅在完整检查通过后登记实际输出目录，并保留既有淘汰记录。脚本不生成正式报告正文。

## 3. 实验结果

### 3.1 有效性与覆盖

[`smoke.json`](results/mapping_cost_accounted/smoke.json) 为 **660/660**：原有映射检查 13/13、占用 144/144、成本契约 503/503，其中包括上述 416 组独立事件对拍。[结果守恒检查](results/mapping_cost_accounted/validation.json)覆盖 **4248 条结果**，失败为零；四条压力序列完整保存 4096 步。缺省、对照、单因素和优化网格均有可行结果。

容量预约 **62/64 可行**。两项超限均为 Llama C0、tile=2048、双缓冲和 K/V 同块预取：连续布局 17,113,792 B，分页 17,183,936 B，超过 16 MiB。超限配置完整保存在 [`capacity.json`](results/mapping_cost_accounted/capacity.json)，不进入性能最优集合。

事件证据同时确认：Llama C2 分页 4K、元数据分离时有 1024 次 KV 读事务；C5 第 128 token 的 Key 刷窗写入为 81,920 B；第 255 token 的 Value 尾页写入为 9,600 B、读改写读取为 8,960 B，残差搬移另计 SRAM。

### 3.2 缺省映射

下表为 Llama、分页、T=4096、tile=128、单缓冲、分开读取、单端口和 split=1 的一层一步。HBM 包含全部读写及 Q/O；动态能量单位为 μJ（1 μJ=10⁶ pJ）。原始分解见 [`default_grid.json`](results/mapping_cost_accounted/default_grid.json)。

| 格式 | 周期 | 动态能量 / μJ | HBM / B | SRAM 峰值 / B |
|---|---:|---:|---:|---:|
| C0 | 1,243,058.67 | 748.40 | 16,859,136 | 423,104 |
| C2 | 1,228,274.94 | 361.31 | 4,753,408 | 235,712 |
| C3 | 1,542,222.94 | 1,051.83 | 4,753,408 | 252,096 |
| C5 | 1,231,421.45 | 379.42 | 5,279,104 | 834,752 |

C2 相对 C0 的 HBM 约 0.282 倍、动态能量约 0.483 倍、周期约 0.988 倍。C2 的组件服务周期中，广播为 786,432，QK 和 PV 各 133,120，SRAM 为 77,757.25，解量化为 65,536，KV 读取 DMA 为 21,102.59；在该供给参数下，压缩降低 DMA 工作量，但广播和计算仍占主要时间。动态能量中，MAC 为 169.71 μJ、HBM 为 148.31 μJ、SRAM 为 33.48 μJ；不能仅根据 HBM 字节计算总收益。

Qwen 分页缺省 C0/C2 周期分别为 1,024,194.56 / 1,020,917.69，动态能量为 439.58 / 246.03 μJ。两种几何均呈现较大的流量与动态能量差异、较小的缺省周期差异。

C3 相对同映射 C2 的周期为 **1.256 倍**，动态能量为 **2.911 倍**。在 T=4096 的满页提交步，读侧 K 逆旋转为 134,217,728 MAC，写侧旋转为 1,048,576 MAC，输出逆旋转为 131,072 MAC；读侧旋转服务时间为 278,528 周期。不同追加步的写侧旋转随满页提交变化，不能把该满页步的写侧动作当作逐步平均值。

### 3.3 映射与资源对照

Llama C2 的 GQA 展开对照保留 16,777,216 次 QK MAC 和相同 PV 工作量，QK 服务时间为 532,480 周期，共享映射为 133,120 周期；总周期为 1,726,282.72，HBM 为 18,909,184 B。其负担来自重复供给和阵列行利用差异，而非少算查询头。

单端口下请求并行 2/4 个 KV head，活动供给仍为单路，周期不变。split=1/2/4 的 QK 服务周期相同；总周期分别为 1,228,274.94 / 1,228,258.69 / 1,228,224.19。几十周期的差异来自局部与最终归并的位置及访问计量，不能解释为 split 的实质并行收益。

[`optimized.json`](results/mapping_cost_accounted/optimized.json)的 16 格均在 24 个候选中选择 tile=128、双缓冲、K/V 同块预取、split=4、共享 GQA。实际活动通路仍为 1；split=4 相对同设置 split=1 的细小优势不超过本模型未校准参数的不确定性。Llama 分页优化结果：

| 格式 | 周期 | 动态能量 / μJ | SRAM 峰值 / B |
|---|---:|---:|---:|
| C0 | 1,218,818.99 | 748.38 | 1,571,520 |
| C2 | 1,207,781.05 | 361.29 | 630,464 |
| C3 | 1,521,729.05 | 1,051.81 | 646,848 |
| C5 | 1,212,741.58 | 379.40 | 1,262,272 |

优化 C2 相对优化 C0 周期约减少 **0.91%**、动态能量约减少 **51.7%**。连续 C0 也使用有界预取并可双缓冲：Llama 连续优化点为 1,217,177.52 周期、SRAM 峰值 1,501,376 B；不以整段历史驻留削弱 FP16 对照。

[`resource_variants.json`](results/mapping_cost_accounted/resource_variants.json)单列增加操作数端口的结果。Llama C2、双缓冲和同块预取时，跨头端口 1→4 的周期为 1,207,831.80→1,008,151.80，SRAM 峰值为 456,896→555,392 B；四端口 split=4 为 1,009,314.42 周期、1,884,032 B。两类方式都受共享 DMA 和总供给限制；增加端口、地址队列、操作数组及路由控制属于额外资源，没有面积校准，不能声称等面积加速。

### 3.4 压力轨迹与敏感性

[`pressure.json`](results/mapping_cost_accounted/pressure.json)保存所有步骤及均值、P95、P99、最大值。下表为分页缺省映射的一层一步统计：

| 格式 | 周期均值 | 周期 P99 | 周期最大值 | HBM 均值 / B | 动态能量均值 / μJ |
|---|---:|---:|---:|---:|---:|
| C0 | 5,126,065.15 | 5,277,912.37 | 5,280,587.52 | 69,193,728 | 3,075.96 |
| C2 | 5,061,623.56 | 5,211,511.74 | 5,214,167.47 | 19,472,512 | 1,484.90 |
| C3 | 6,346,768.31 | 6,535,109.82 | 6,537,603.47 | 19,472,512 | 4,309.43 |
| C5 | 5,058,009.50 | 5,207,679.88 | 5,210,549.86 | 21,530,944 | 1,551.13 |

C5 每步保留量化、残差读写、Value 尾页读改写及 Key 刷窗字段，能够定位成本起伏。不同长度自身带来的增长与刷窗动作同时存在，整体 P99 不单独归因于刷窗。

开发单因素中，解量化吞吐为 64/128/256 元素每周期时，Llama C2 周期为 1,293,810.94 / 1,228,274.94 / 1,195,506.94，C0 保持 1,243,058.67。扫描点之间存在周期方向变化，只能给出 **64–128 元素/周期之间的区间**，不能外推精确交叉值。HBM 为 0.25 TB/s 时，C0/C2 为 1,293,636.08 / 1,242,535.16 周期；2 TB/s 时改善受 DMA 对应的 SRAM 入口限制。

[`implementation_sensitivity.json`](results/mapping_cost_accounted/implementation_sensitivity.json)将辅助吞吐同时取 0.5/1/2 倍。C2 相对 C0 的周期由约低 3.78%、低 1.19%，转为高 2.17%；缺省点的小幅周期优势不稳健。阵列启动成本另取 0/2/16 周期，不将缺省值称为实测延迟。

[`sensitivity.json`](results/mapping_cost_accounted/sensitivity.json)覆盖 HBM、MAC、SRAM、解量化、softmax、广播、量化、打包、控制和转换的单位能量，以及 DMA 启动成本。已测单因素点中，C2/C0 动态能量比约为 **0.400–0.587**，方向保持；这不是多参数同时变化的最坏界，也不是统计置信区间。在 1 GHz 参考时间下，C2 缺省点额外 10/50 mW 漏电积分为 12.28/61.41 μJ，主表仍不包含这些假设漏电项。

## 4. 分析与讨论

本模型支持的主要优势是压缩的流量和动态能量降低。优化 C2 的周期优势约 0.91%，远小于能量差异，且能被合理的供给吞吐变化反转。因此不能将该点推广为压缩必然加速，也不能用解量化一项解释全部性能。后续尺度与组供给研究需要同时检查转换、广播、SRAM 和阵列行利用，并对优化 C0 使用同样的预取与资源预算。

逻辑 split 可以组织独立状态，物理并行仍需要操作数端口和阵列份额。单端口下，split=4 的微小差异主要是归并安排；新增端口后跨头和 split 才出现明确周期变化，但容量和互连资源也随之增加。没有面积证据时，资源变体只能用于说明瓶颈和权衡，不能作为公平同资源收益。

C3 混合路径保留功能参考价值，读侧 K 逆旋转仍是相对 C2 的主要额外动作。在已测缺省与敏感性条件下，其动态能量和周期均高于 C2。本实验不比较两者的整模质量，因而只能判断给定路径的成本差异，不能据此否定旋转对量化质量的潜在价值；当前路径也不等于纯 Q/O 优化成功。

容量结果说明开发 tile 和大缓冲预约应分开解释。连续 FP16 可以有界读取并使用双缓冲，而 2048-token、双侧、双缓冲预约仍可能超出 16 MiB。容量可行不等于性能最优；一次预约超限也不等于该格式所有流式映射均不可行。

## 5. 局限与有效性

- 周期与能量是冻结实现假设下的架构估计，未经过 RTL、SRAM 宏、互连或整芯片校准；不代表整模 TPS、综合后频率或硅片绝对能耗。
- output-stationary 映射、固定端口分配、辅助吞吐、启动延迟和单位能量会影响结果。敏感性已显示周期方向反转；单因素能量方向保持不能替代联合不确定性或独立配置验证。
- 事件对拍核验声明缓存布局的逻辑/物理动作，不模拟 Python 分配器，也不证明真实 HBM 控制器的突发、bank 冲突、随机页行为或多 DMA 引擎性能。连续地址合并与分页范围读取是明确区分的模型策略。
- 额外端口的缓冲、队列、广播和控制进入计量，但尚无面积归一化及物理互连延迟证据；资源变体不作为等面积对照。主能量仅覆盖所列动作，未声称覆盖完整芯片时钟树、静态功耗或板级功耗。
- batch=4 为时间复用；压力序列是相关的几何轨迹，不是独立统计样本。PPL、任务质量、正式生成、公开 GPU 内核以及步骤 8/12 的独立配置均未在本实验验证。
- 本报告复用已有 Accelergy 卡片和台账的能量来源及边界，没有增加文献来源，也不构成全领域或历史性能数字复核。

## 6. 结论与后续工作

在相同缺省资源与共享搜索空间下，C2/C5 相对优化 FP16 减少 HBM 字节和模型动态能量；C2 的缺省周期收益较小且不稳健。单端口的逻辑 split 不增加物理计算通路；增加端口可能改善阵列使用，但须在后续阶段核对面积和互连代价。C3 混合路径成本较高，继续作为保留读侧 K 逆旋转的功能基线，不作为已经成立的成本优化。

步骤 7 的研究应以这些强基线为对照，验证尺度处理和组供给能否产生额外收益，并计入全部新增动作。步骤 8 再按冻结协议检查归并、布局和独立组合；正式质量及 GPU 对照仍属步骤 9。当前结果不替代这些后续验收。
