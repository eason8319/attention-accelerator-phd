# R2 阶段详细计划：流式通路、探索实验与创新评估

本文件细化[长线研究计划的 R2 阶段](../../docs/research_plan.md#r2-overview)，集中维护实验内容、比较口径、审核要求和阶段末评估规则；执行状态与评估处置只在[里程碑](../../docs/progress/milestones.md#r2-review)维护。

基础通路的技术验收、探索实验的完成情况、创新点是否成立分别判断。完成探索不保证正向收益、创新成立或论文发表；候选失败不自动否定已完成的基础能力，也不放宽基础技术门槛。

**目标**：完成“物理低比特缓存 → 流式 Attention → 周期与能耗模型 → 关键 RTL 与首版综合”的基础闭环，并验证下列候选机制。默认低比特路径不物化完整高精度 KV tile；允许格式定义内的 FP16 残差窗，但单独计量，不额外保留历史 KV 的完整浮点副本。

## 1. 基础通路与研究边界

1. 真实物理打包、追加与分页：载荷、scale/min 或 zero-point 对齐 group、页及 DMA 边界，核验尾页与 KIVI 刷窗语义。
2. 完整功能通路：有界流式解码、QK、online softmax 的最大值/归一化量/部分输出、PV、跨分段归并和最终归一化；优化 C3 的 Q/O 端变换，并计入新增 KV 的写侧旋转。
3. 公平映射：比较 GQA 共享、跨 KV head 并行和 KV-split，明确不同 split 的独立地址供给、端口、互连及归并代价；不直接用逻辑并行度推定阵列利用率。
4. 完整计量：区分缓存占用、逻辑读写、物理 SRAM/HBM 事务；计入量化、打包、刷窗、元数据、对齐、广播、背压及输出重缩放。均值、尾延迟与逐步轨迹分别报告。
5. 硬件证据：关键前端、完整小 Attention 通路与小阵列经过 Verilator 验证和首版综合；按组件、形状、启动延迟、持续吞吐及端口竞争校准，而非采用三个统一修正系数。

**R1 动机的适用范围**：引用 [R1 总报告](../r1_kv_baseline/REPORT.md)、[模拟器报告](../r1_decode_sim/experiments/decode_sweep/REPORT.md)和[敏感性报告](../r1_kv_baseline/experiments/kv_sensitivity/REPORT.md)，不复制历史结果表或改写原始结论。C2 的 decode、tile=2048 已支持单缓冲；新实验关注双缓冲、预取与容量边界。“最近 128 token 决定误差”尚未得到真实模型证据支持；KIVI 的 K 残差长度随刷窗变化，也不能等同于始终保护最近 128 个 K。

## 2. 候选创新与新增实验

下表定义研究假设，不预设其成立。前四项应完成约定探索或记录经审核的停止理由；后三项是基础能力和计量验证，其性能收益可以不成立，但功能与证据要求不能因此省略。

| 方向与 R1 动机 | 待验证假设 | 主要对照与实验 | 观察指标与否定条件 |
|---|---|---|---|
| **尺度处理与 GQA 复用协同**：串行解量化抵消部分压缩收益，不同格式的尺度分组不同 | 根据尺度分组和共享程度选择执行方式，可能优于单一固定方式 | 对同一编码载荷比较共享流式解码、尺度折叠及按配置选择；覆盖 per-token/per-channel 分组、GQA 共享比 1/2/4/7/8，保持资源与数值口径可比 | 尺度操作、转换、重复解码、周期、缓冲与能耗；若仅优于 R1 弱映射，或计入全部成本后无增量收益，则不支持创新 |
| **有界缓冲下的组供给调度**：R1 尚未验证消费者进度、缓冲释放和供给之间的关系 | 按消费者完成状态推进供给，可能减少停顿或重复工作 | 固定调度对比进度驱动调度；组缓冲取 2/4/8，分别消融组驻留、广播复用和供给重叠；与尺度处理联合研究，避免重复计算贡献 | 缓冲峰值、停顿、广播和控制开销、周期与能耗；若额外端口、状态或互连成本抵消收益，则不保留为创新 |
| **缓存页与输出归并范围解耦**：R1 页表字节小，但尚未计入真实页访问与归并代价 | 固定物理分页下选择归并范围，可能改善缓冲与重缩放之间的权衡 | 页长保持 16 token，归并范围取 16/64/128/512；比较每页归并、最佳固定配置、成本预测选择及小范围穷举参照 | 部分输出读写/重缩放、页等待、SRAM、周期与能耗；若预测选择不能在独立配置上改善固定策略，则仅作为配置分析 |
| **压缩收益边界**：字节下降未自动转化为模拟时延下降 | 包含供给、写侧和缓冲约束的模型可预测压缩的周期/能耗交叉点 | 扫描带宽、SRAM、解量化吞吐与 GQA 共享比；区分开发配置和未用于调整的组合配置 | 预测误差、交叉点与参数敏感性；若只能拟合已测配置，或结论被合理参数变化推翻，则不作为独立模型贡献 |
| **旋转域计算与缓冲释放**：C3 读侧旋转昂贵，完整解码 KV 占用 SRAM | 优化变换位置并取消完整解码缓冲，可能支持更深预取或双缓冲 | 同一量化载荷下比较 Q/O 端变换与优化后的逐组逆旋转；比较单/双缓冲、不同 tile；FP16 对照也消除不必要副本 | 数值差异、存活缓冲、变换/写入成本和停顿；不得仅删除模拟器字段就认定容量节省，亦不保证 DMA 事务随 tile 等比例减少；作为强基线 |
| **追加、刷窗与元数据访问**：R1 主流量证据限于读取，物理布局成本未闭合 | 写侧竞争和元数据布局可能改变平均成本或尾延迟 | 采集 append、量化、打包、刷窗和页访问；分别比较元数据共址与分离布局，保持编码不变，记录残差实际驻留层级 | 分层读写、对齐浪费、量化动作、均值及刷窗附近延迟；若无周期尖峰或共址不改善事务，则保留该结果，不制造写放大结论 |
| **格式切换接口**：已有低比特历史和 FP16 残差共存 | 明确标签、尺度组和旋转域后可复用一条受控通路 | 验证现有历史/残差调度及格式边界；K/V 尺度域分别处理，旋转域混合需明确部分输出的坐标和归并方式 | 标签及地址成本、切换停顿、刷窗/尾页正确性；若不能保持语义，则收缩支持范围，不声称零增量或任意格式兼容；仅作 R3 接口准备 |

**数值与收益约束**：尺度折叠不自动产生整数点积，Q 和概率的运算类型必须明确；尺度操作减少倍数不得写成 Attention 加速倍数。非对称格式区分整数 zero-point 与 R1 KIVI 的加性 min，保留各组偏置修正。C3 保持当前量化载荷与旋转定义，验证浮点重排误差；Q/O 变换、写侧旋转与 GQA 共享比例均计入。格式标签不预设 PTE 有空余位，元数据共址不预设减少实际传输字节。

**后续候选**：FP8 尺度、INT8 残差和 Q/概率低精度 MAC 分别涉及元数据精度、残差再次量化及算术精度变化，不能合并为一次布局优化。R2 默认不启动其完整整模和 RTL 扩展；阶段末依据资源、前置证据和研究价值决定是否转入 R3。完整混合精度分配与联合搜索仍属于 R3/R4。

## 4. 实验范围与质量要求

以下为 R2 专用设置，不反向修改 R1 的协议、原始数据或完成范围。实验执行前固定模型/数据/实现版本、随机种子、任务模板、生成预算与截断策略；参数进入共享配置及各批次 run_config.json，禁止根据正式结果修改门槛或挑选有利样本。

| 项目 | R2 范围 |
|---|---|
| 正式模型 | meta-llama/Llama-3.1-8B-Instruct 与 Qwen/Qwen2.5-7B-Instruct；GQA 共享比分别为 4 与 7；`Qwen/Qwen2.5-0.5B` **base** 仅用于开发检查，不得用 Instruct 快照替代 |
| 主要格式 | C0 FP16、C2 INT4 group=32、优化 C3 INT4+BDR、C5 KIVI 风格 INT4 group=32/残差窗=128；沿用 R1 格式编号，C1/C4 作为回退或边界参照，不扩展为完整 RTL 主线 |
| 窗口与布局 | 4K/8K/16K/32K，contiguous/paged 成对评测；精度必须经过实际压缩缓存及流式读路径，不复用 contiguous 数字充当 paged 实测 |
| PPL | 完整 WikiText-2 test，stride=512，逐模型/窗口/布局与同批 C0 配对，保存实际计分 token 数与 NLL；每窗用 prefill 建立压缩 KV，只对新增计分 token 走流式读路径；全程逐 token 另用冻结小集，不作为 5%/3% 分母；不同 tokenizer 不强行采用相同 token 数 |
| 长上下文任务 | RULER 的多键检索、多查询检索、变量追踪、词频聚合四类代表配置；4K/16K/32K，每项每长度固定 100 个样本；采用固定版本的官方数据与评分定义 |
| 真实任务 | LongBench 的 qasper、gov_report、hotpotqa、lcc 四项完整测试集；遵循固定官方模板和评分，记录实际长度，不用填充制造长上下文能力 |
| 连续生成 | 双模型、四主格式、paged 路径，4 个固定输入执行 D(16384,1024)，保存全部步骤；窗口预算包含输入与生成，attention 成本与端到端测量分别报告 |
| 更长压力 | 64K/128K 仅做架构或轨迹测试，标明合成/几何/实测来源，不宣称对应整模质量已验证 |
| 架构包络 | 默认 1,024 MAC、16 MiB SRAM、1 TB/s；1 GHz 为理论参考，综合频率另报。带宽扫描 0.25/0.5/1/2 TB/s，SRAM 4/8/16 MiB，解量化吞吐 64/128/256 元素每周期；采用默认点、单因素及独立组合点，避免无目的全组合 |
| 并行与容量 | batch=1 为主、batch=4 为压力；KV-split=1/2/4，并列比较跨 KV head 并行；tile=2048 保留为容量与缓冲边界检查，页与归并范围按 R2 候选实验设置 |

质量与测量要求：

- 相对同设置 C0 的 PPL 增加不超过 **5%** 为工程门槛，**3%** 为优选目标，不作为论文发表标准。任务分统一到 0–100，套件平均下降不超过 2 个百分点、单任务不超过 5 个百分点为预定筛选标准；基线本身得分低时不据此宣称任务能力充分。
- 保存逐样本结果，配对 bootstrap 2,000 次报告 95% 置信区间。未能支持非劣结论时标明不确定性；不将确定性模拟器的重复运行当成独立统计样本。
- 分开检验量化损失和实现误差：先对照同一 codec 的高精度参考，再比较 C0 任务质量。FP32 功能检查采用 atol=1e-5、rtol=1e-4；RTL 对照同运算顺序和舍入规则的参考，硬件算术对同 codec 高精度参考的相对 L2 不超过 1%，近零输出另查绝对误差不超过 1e-5。发生非有限值或不满足阈值时按失败分析，不通过更换参考掩盖问题。
- 固定模型权重和运算精度，不引入权重量化。保留尾页、残差刷窗、非整齐头分组、掩码、极端分数与背压检查；复用 P1 online softmax 前独立关闭未通过项。
- 公开 GPU 内核预热 20 次、测量 100 次，独立执行 5 轮，报告时延分布和实际环境；功能参考实现、GPU 实测与 ASIC 架构推算分别标识，不把 attention-only 时延写成整模吞吐。CUDA、BitDecoding、SAW-INT4 的隔离、冒烟顺序与官方路径二选一见 [§4.1 GPU 对照](#r2-protocol-review) 与共享配置 `gpu_kernels`，不升级 R1/步骤 2 的 `torch 2.5.1+cu121`。
- 同格式消融固定编码、资源和输入；增加互连/控制资源时补充面积预算归一比较。能耗按动作次数及每动作能量、漏电持续时间建模，记录参数来源、工艺/电压/频率及敏感性；缺失参数不按零处理，不仅对 component_cycles 乘常数。
- 组件校准与完整小通路验证并行约束结论，范围限定于已覆盖的形状和配置。局部综合不等于整芯片 PPA；收益方向若随合理参数变化而反转，应报告适用条件。

R2 默认采用开源 Verilator、Yosys/OpenROAD 与公开 Nangate45 平台，实际版本和可用性在资源检查步骤固定。逻辑综合、SRAM 估计和片外存储能耗分别说明来源，不混为同一工艺下的整芯片测量。

### 4.1 首轮协议审核口径

本节细化上述约定，配套的机器可读参数在 [evaluation_protocol.json](experiments/configs/evaluation_protocol.json)；协议版本为 `r2-evaluation-v2`，取代 `r2-evaluation-v1` 将全程逐 token 前缀作为质量门的口径。v1 的算量证据仍见[资源与最小算术报告](experiments/arithmetic_feasibility/REPORT.md)，该报告中的 89.90 GPU 天不按 v2 重算。参数值在配置中维护，本节说明解释与判定规则。批准与步骤状态只见[里程碑](../../docs/progress/milestones.md#r2-review)；本 JSON 不是批准记录。

- **前置边界**：R1 四项入口门槛按其[总报告 §6](../r1_kv_baseline/REPORT.md#6-结论与后续工作)接受。R1 的名义 INT4 字节、完整解码及 contiguous 精度不充当 R2 的物理打包、流式路径或 paged 精度证据；实现从 C2 开始，C0 同步作基准，再接入 C5/C3。
- **模型与算术**：正式模型固定权重和 tokenizer 的同一仓库 revision；开发模型固定为 `Qwen/Qwen2.5-0.5B` **base**，已有 Instruct 快照不能替代。权重不入库。本机与集群均遵守根规则[模型权重缓存](../../AGENTS.md#model-weight-cache)：每台机器只使用该机 `HF_HOME`（本机默认 `/mnt/f/hf-cache`，集群默认 `$HOME/hf-cache`），按 ID 与 revision 核验，不把权重复制进仓库。`Qwen/Qwen2.5-0.5B-Instruct` 只供 R1 开发/冒烟，`Qwen/Qwen2.5-0.5B` base 只供 R2 开发检查，二者不能互换。开发模型运行前须具备 0.5B base，步骤 9 前须具备 Qwen2.5-7B-Instruct。整模统一 FP16 权重、输入激活和 KV 残差，不量化权重，不自动切换 BF16，不修改模型原有 RoPE/context 配置。软件功能参考对反量化、QK、softmax 和 PV 使用 FP32，输出按模型接口转回 FP16；误差归约复用 R1 float64 口径。RTL 运算位宽、舍入和近似函数须在实现前单独固定，不能将 FP32 参考精度当作硬件已实现精度。1 ns 探针未通过只保留为步骤 2 负结果，不回头优化该整数乘加。
- **格式不变**：C2/C3 沿 channel 维分组，使用 R1 对称网格 `[-7,7]`，不能擅自换为 `[-8,7]`。C3 沿用 block=32、seed=0 的旋转，K/V 写侧都计入，候选间复用相同编码载荷和旋转矩阵哈希。C5 的 `min` 是加性 FP16 元数据，不是整数 zero-point；K 的刷窗与 V 的滑动残差分别遵循 R1 语义。物理 pack 只能改变表示，不能重算统计量掩盖不一致。
- **窗口语义**：质量评测的窗口是输入与最大生成长度之和；RULER 按官方生成器预留输出预算，最终模板/tokenizer 处理后再次校验长度。LongBench 每个窗口都运行四项完整测试集，只对过长输入作确定性中间截断，保留两端，计入模板开销；不填充短样本，不按分数或长度筛样本。每个模型内各格式与双布局使用相同输入 token、样本顺序和生成规则；不同 tokenizer 分别保存长度和哈希。
- **任务版本与模板**：[RULER](../../docs/recent_works_comparison.md#ruler) 使用已固定提交的原版四个子任务，关闭额外 task 参数覆盖；[LongBench](../../docs/recent_works_comparison.md#longbench) 使用原版 `LongBench/` 子目录，既不是 v2，也不是 LongBench-E。使用固定官方任务文本和评分函数；Llama/Qwen 的问答与摘要外层调用各自固定 tokenizer 的 chat template，显式空 system message、无工具，Llama 模板日期固定，不注入运行日期；`lcc` 遵循官方例外，不加 chat 包装。RULER 使用官方任务正文及 answer prefix、模型 chat 包装，属于明确登记的模型适配，不能称为无改动官方整套复现。必须保存最终模板、token IDs 和停止 token；首个任务正式运行前先核对适配样例。
- **PPL 计分**：固定 `Salesforce/wikitext` 的 `wikitext-2-raw-v1/test`，按原始行用双换行连接，tokenizer 不自动加特殊 token，最前加一个模型 BOS；无 BOS 时不添加。使用完整语料，stride=512，首窗口从可预测的第二个 token 开始，后续只计新增 token，各目标恰好计分一次。窗口重置缓存后，用预先定义的 **prefill 写入实际压缩 KV** 建立该窗上下文，仅对计分区间沿压缩缓存和流式读路径做 teacher forcing；保存窗口起止、计分区间、NLL 与 token 总数。禁止用原生 Hugging Face SDPA 充当 C0，禁止复用 R1 contiguous PPL 充当 paged 或流式精度，禁止因耗时缩短语料。该口径相对 v1 改变了前缀处理语义，不是等价加速；v1 的全程逐 token 前缀不再作为 5%/3% 质量门。
- **流式路径小集**：与质量门分开。使用同一 WikiText token 流、固定起点 `[0, 4096, 16384, 32768]`、长度 257、双布局与四主格式，从窗口第一个 token 起全程逐 token 走流式读路径，覆盖尾页、非整齐分组、KIVI 刷窗、全掩码与背压。该集只判断实现误差，不进入 PPL 非劣结论。
- **连续生成**：每模型从固定 WikiText test token 流的四个预定起点截取 16,384 token，不循环填充。逐格式自由贪心生成 1,024 步，保存首次 EOS 位置；为完成固定轨迹，EOS 后继续的部分明确标记为压力后缀，不纳入自然回答质量解释。teacher-forced 功能核对与自由生成分开；4 个输入属于配对轨迹，不把 1,024 个相关步骤当作独立样本。
- **质量判定**：PPL 按模型×窗口×布局逐格与 C0 配对，不能以平均值掩盖失败。任务分按模型×窗口×布局分别形成两个套件的等权任务平均；RULER 与 LongBench 不混合平均。差值取“候选−C0”，点估计满足既定退化上限只是筛选；95% 配对 bootstrap 区间下界也不低于相应负阈值，才支持该格的非劣结论。区间跨门槛记为证据不足；未完成、运行失败和低分 C0 单列，不计为通过。bootstrap 在每项内按样本 ID 配对重采样，再等权汇总；不跨模型合并样本。
- **数值判定**：相对 L2 对每个 query head 的输出向量计算并报告最大值；参考范数非零时必须满足原定 1% 上限。参考 RMS≤1e-6 时另要求最大绝对误差≤1e-5；零范数相对 L2 记 null，只判绝对误差。全掩码输出须定义为零，空分段不参与归并；允许掩码编码中的 −∞，有效分数与输出不得出现 NaN/Inf。舍入边界、尾页、刷窗、非整齐分组和背压是必测有效性条件，不能用平均误差抵消单项失败。
- **GPU 对照**：CUDA 扩展、BitDecoding、SAW-INT4 不得混装进 R1 或步骤 2 探测环境（`torch 2.5.1+cu121`）。本机与集群均遵守根规则[隔离 GPU 运行时](../../AGENTS.md#isolated-gpu-runtimes)。CUDA 另建只用于编扩展的环境：`CUDA_HOME` 指向 nvcc 12.4，或 toolkit 与该隔离环境 PyTorch 一致。BitDecoding 用隔离 venv、固定提交 `ae0d836…`，补 flash-attn / ninja，按作者 `setup.py` 编 sm80；先最小 shape 功能冒烟，再谈步骤 9 的 20/100/5 轮口径。量化网格若对不上 C2/C3，标成同 GPU 的作者格式，不得改名为项目 C2。SAW 官方 FA3 要求 H100/H800，协议附件二选一：有该设备时，官方 fa3+triton 是唯一未改动作者路径；否则步骤 9 放弃官方 SAW kernel 时延，C3 只与本仓库旋转定义及 Q/O 变换对拍，论文与作者文档继续当机制参照，不报 Ada 上的官方 TPS。换 FA2 后端必须另标适配，不能叫 SAW 官方复现。Flash-Decoding 与本仓库 C0 的 GPU 时延仍可在 Ada 上测，不依赖 SAW。机器可读字段在共享配置 `gpu_kernels`。

### 4.2 公平对照与成本边界

| 对照角色 | 必须保持一致 | 允许回答的问题 |
|---|---|---|
| 同 codec 高精度参考 | 相同已编码 K/V、scale/min、输入 Q、mask、旋转和残差状态 | 只判断实现误差，不承担性能基线角色 |
| 先展开再计算 | 相同编码、数值标准与总资源；记录完整解码缓冲 | 量化格式确定后，流式化本身的影响；不得作为创新的唯一基线 |
| 优化 FP16 | 相同模型、输入、页长、总 SRAM/MAC/带宽；同样允许合理 GQA 复用、预取和 split | 满足质量约束后的压缩净收益；不设置额外无用副本削弱 C0 |
| 优化同格式共享流式解码 | 相同载荷与资源搜索空间；按真实 KV head 供给并复用 | 尺度、供给和归并候选的增量收益；固定策略也在开发集上选优后冻结 |
| 公开 GPU 内核 | 同 GPU、dtype、形状、实际可支持的格式与范围；官方 SAW FA3 仅 H100/H800；BitDecoding 网格不对齐时另列作者格式 | GPU 平台内的实测差异；无 H100/H800 则省略官方 SAW 时延/TPS；格式或设备不兼容须另列，不伪称同格式或官方复现，不能与 ASIC 周期算跨平台加速比 |

默认 tile=128，开发比较 128/512，2048 仅作容量边界。1,024 MAC 是统一运算预算，split、并行 head、广播或解量化复制不能凭空增加 MAC、端口或吞吐；共享预算中列出 Q、压缩组缓冲、残差、页表/标签、scale/min、score、partial O 和 DMA 队列的峰值存活占用。FP16 也从相同允许的映射空间选优。页长固定为 16，页表项仍为每项 8 B，标签另列，不假定有空余位。

基础记账以每层每步为原子事件，再按实际层数及生成步数汇总；全模型与 attention-only 分开。分别报告有效载荷占用、实际已分配字节、逻辑读写、SRAM/HBM 实际事务与对齐浪费。HBM bytes/token 主结果包含读和写；可比 R1 的逻辑读列单独保留。append/量化/刷窗、页查找、广播、控制、重缩放与归并均需入账，报告均值、P95、P99、最大值及刷窗轨迹。事务粒度、SRAM bank/端口/延迟、DMA 队列和每动作能量须在对应模型运行前固定并给出处；步骤 2–6 补齐这些实现参数，缺失即不得出具物理流量或绝对能耗结论。

### 4.3 开发配置与独立验证

各组合的精确参数在共享配置 `architecture` 中维护。开发集采用默认点及单因素变化，另以组合点检验交互；独立集是预先登记、不得用于调参的组合，不是新的模型能力声明。

- 开发默认几何取 Llama 的单层形状，GQA=4；单因素覆盖两模型几何、全部约定带宽/SRAM/解量化吞吐/GQA、batch、split、组缓冲和归并范围。合成 GQA=1/2/8 的结果标明几何来源，不冒充第三个整模。
- `bandwidth_limited`、`supply_limited`、`capacity_limited` 三组独立组合在步骤 8 使用；`qwen_shared_pressure`、`llama_long_pressure` 两组留到步骤 12。双布局和主格式成对覆盖；容量不足也是需保留的预测和结果，不自动删除不可行点。独立组合的参数可以预知，其结果只能在对应冻结之后查看；已打开结果的组合不再回归开发集。
- 页与归并选择在开发集上确定最佳固定策略及预测器；独立点的穷举仅作事后 oracle 参照，不反向用于选取部署策略。记录相对最佳固定策略、oracle 差距、周期/能耗预测相对误差和可行性判断；交叉点只在带宽相邻实测点之间给区间，没有交叉则报告扫描范围内未观察到，不外推精确值。
- 四项探索沿用 §2 的假设、消融和否定条件。基础能力按 §6 验收；探索工作完成、出现收益和创新成立分别判断。不预设最小加速倍数，不把独立验证后调整的新版本当作未见过结果的版本。

### 4.4 版本锁定与后续依赖

共享配置保存本轮公开模型/数据集 revision、评测代码提交和 R1 格式源码哈希。它是协议输入，既不证明权重已下载，也不证明当前机器可运行。公开 GPU 内核、Python/CUDA/RTL/综合库版本及资源预算由步骤 2 核验；内核构建与官方 SAW 时延属于步骤 9 前置，不挡步骤 3–8。新实现入口、实际执行源码、模板/数据/输入哈希和所有已解析参数进入每批 `run_config.json`，保存共享配置的 SHA-256，不接受 `main`、`latest` 或未解析占位符作为运行版本。

本轮预设参数的任何语义修改都要升协议版本并返回用户审核；单纯补入已约定来源的实现提交或文件哈希，在其所属步骤提交审核。`r2-evaluation-v2` 是对 v1 在完整语料成本与 SAW 设备不兼容上的已审核收缩：不换模型、不降 PPL/任务门槛、不删任务。模型访问不可用、GPU 格式不兼容、FP16 非有限值或综合不可行时仍停在对应步骤提出具体收缩，不自动越过审核。

## 6. 基础验收与阶段末创新评估

**基础技术验收与进入 R3 的门槛**保留，单独检查：

- 默认低比特路径不物化完整 FP16 KV tile，物理打包、分页、追加及残差语义正确；
- online softmax 包含 partial O、跨分段归并和最终归一化，满足事先约定的数值及任务质量要求；
- 在同等精度或明确退化点上，相对优化 FP16 KV 展示 bytes/token 与模拟 energy/token 改善，分别报告片上、片外读写和不确定性；满足同一精度上限不等于精度完全相同；
- 完成关键模块与完整小通路验证、首版综合和相应校准，至少一个关键模块具有综合报告；
- 结果、源码、配置、依赖和证据角色可追溯。与先解压再计算及优化流式基线的比较均保留，不把片上缓冲减少写成必然减少 HBM 字节。

基础精度、功能、证据完整性或原定硬件收益门槛未满足时，记录未通过原因，或提出经用户审核的明确收缩方案，不能以“探索允许失败”替代技术验收。候选创新失败不自动否定已经完成的基础能力。

**探索完成情况**按已约定的对照、消融、独立验证和结果分析判断，允许有效否定结果；未完成项保留范围及缺失证据。若不再值得继续或受资源限制，记录经审核的停止理由，不把未运行记为否定结果。创新候选不设置“必须加速若干倍”或“必须降低 10% 能耗”的通过条件。

**阶段末创新评估**在基础实验和校准后逐项进行；未完成必要校准的候选只能保留为证据不足。评估六个问题：

1. 有效性：数值、缓存语义和原始数据是否可信？
2. 增量收益：相对优化后的同格式基线，是否仍有可重复的独立收益？
3. 成本完整性：控制、互连、缓冲、写入、归并和元数据是否全部入账？
4. 适用范围：双模型几何、独立配置和压力测试支持哪些范围，在哪些条件下失效？
5. 新颖性：结合阶段末相关工作复核，具体机制与最近研究的差异是否仍成立？
6. 后续价值：继续深入、作为基础能力保留，还是停止？

| 评估结果 | 处置 |
|---|---|
| 有可靠收益且存在明确差异化 | 保留为论文候选贡献，列明仍需补足的证据；不保证发表 |
| 有工程收益，但新颖性不足 | 纳入强基线或系统实现，不包装为独立创新 |
| 在声明范围内未发现净收益 | 保留有效否定结果，停止该方向扩展，不外推为所有配置无效 |
| 证据不足 | 标明缺失证据与补测条件，不判为成功或失败 |

正式分析写入所属实验唯一的 REPORT.md；里程碑仅登记状态、处置和证据链接；[长线研究计划](../../docs/research_plan.md)依据评估调整 R3/R4 路线，不另建阶段创新总结文档或复制结果表。

## 7. 文件与证据管理

R2 实验采用与 R1 相同组成：源码入口、results/、experiment.json 和唯一 REPORT.md，记录依赖、配置、来源及结果哈希。可复用的登记与实现模块放在本阶段根目录，实验入口、RTL 探针与保留的冒烟测试留在各实验目录。结果按用途、模型、设置命名，不使用日期或临时步骤编号；保留测试在 smoke/、构建在 build/，正式报告在实验完成、原始结果核验后人工撰写。

具体实现版本和批次参数进入共享配置与 run_config.json，配置、来源、哈希与机器结果沿用 R1 的登记方式。不改写 R1 历史协议、报告和结果，不作无基线倍数承诺。

文件管理遵循项目 [AGENTS.md](../../AGENTS.md)。本计划不承载实验结果表或正式结论；文档修订不代表实验开始，不提前创建实验报告或结果目录。已开展实验的入口与证据角色再加入[实验索引](../../docs/experiments.md)，维护历史仅在既有 [CHANGELOG](../../docs/progress/CHANGELOG.md)简记。
